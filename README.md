# PayBox Platform

ระบบรับชำระเงินผ่าน PromptPay สำหรับเครื่อง ESP32-S3 หน้าร้าน — API, หน้าเว็บผู้ดูแลระบบ
และหน้าเว็บร้านค้า อยู่ใน repo นี้ทั้งหมดและถูก build เป็น Docker image เดียว

ใช้งานจริงอยู่ที่ <https://orca-paybox.com>

## โครง

```
backend/     Node 22 + TypeScript + Express + MySQL 8.4 — API และตัวเสิร์ฟหน้าเว็บ
  src/routes/      endpoint แยกตามผู้ใช้: อุปกรณ์ / ร้านค้า / ผู้ดูแลระบบ
  src/lib/         ตรรกะที่ไม่ผูกกับ HTTP — คิดค่าธรรมเนียม, คิวคำสั่ง, แจ้งเตือน, audit
  src/middleware/  ตรวจสิทธิ์และจำกัดอัตราการเรียก
  db/              schema กับ migration ที่มีเลขกำกับ
frontend/    React 19 + Vite + Tailwind — พอร์ทัลผู้ดูแลระบบและร้านค้าในหน้าเดียวกัน
ops/         สคริปต์ที่รันบนเซิร์ฟเวอร์: สำรองข้อมูล, เฝ้าระวัง, แจ้งเตือน, ปล่อยของ
docs/        เอกสารสถาปัตยกรรม การติดตั้ง และการตั้งค่าความปลอดภัย
```

firmware ของเครื่องอยู่คนละ repo ที่ `paybox-firmware`
ส่วนโค้ด PHP ชุดแรกที่เลิกใช้แล้วเก็บไว้ที่ `paybox-legacy` สำหรับอ่านย้อนหลังอย่างเดียว

## ทำไมทั้งสองฝั่งอยู่ repo เดียวกัน

หน้าเว็บกับ API ถูก build เป็น image เดียว ปล่อยพร้อมกัน และเวอร์ชันเดินไปด้วยกันเสมอ ถ้าแยก repo
commit ที่แก้ทั้งสองฝั่งพร้อมกันจะถูกฉีกเป็นสองอันที่ไม่มีอะไรผูกไว้ และจะมีช่วงที่หน้าเว็บใหม่
คุยกับ API เก่าได้

## เริ่มพัฒนา

```sh
cd backend  && npm ci && npx tsc --noEmit
cd frontend && npm ci && npm run build
```

ค่าที่ต้องตั้งดูใน `.env.example` — ความลับจริงอยู่แต่บนเซิร์ฟเวอร์ ไม่มีในนี้

## ปล่อยของ

```sh
git push
ssh root@$PAYBOX_HOST /opt/paybox/scripts/deploy.sh
```

`deploy.sh` จะหยุดทันทีถ้าเจอไฟล์ที่ถูกแก้ค้างไว้บนเซิร์ฟเวอร์ ต้องสั่ง `FORCE=1` ถึงจะยอมทับ
รายละเอียดทั้งหมดอยู่ใน [`ops/README.md`](ops/README.md)

## สิ่งที่ระบบทำให้อัตโนมัติ

| อะไร | เมื่อไหร่ | อยู่ที่ |
|---|---|---|
| สำรองฐานข้อมูล + ไฟล์อัปโหลด | ทุกวัน 03:00 น. | `ops/backup.sh` |
| ทดลองกู้คืนจากไฟล์สำรองล่าสุด | อาทิตย์ 03:30 น. | `ops/restore-test.sh` |
| เฝ้าระวังเว็บ ฐานข้อมูล และเครื่อง | ทุก 5 นาที | `ops/watch.sh` |
| ตามเก็บรายการที่ค้างสถานะกับ Stripe | ในตัว backend | `backend/src/lib/reconcile.ts` |
